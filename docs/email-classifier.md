# Email classifier

This experiment uses **300 synthetic emails**, generated by `openai/gpt-5-nano`, then labeled by `typesafe-ai/jev` through Vercel AI Gateway. The six categories are `primary`, `promotion`, `update`, `social`, `forum`, and `purchase`. The [task definition](../examples/email/task.json) specifies the boundaries; for example, receipts and delivery notices are purchases, while a personal conversation about buying something is primary.

## Results

Measured on Apple M3 Max, macOS arm64, Node.js 25.6.0, using the unchanged q8 MiniLM encoder and linear head. The split contains **195 training, 45 development, and 60 test emails**; development is further divided into 25 tuning, 10 calibration, and 10 acceptance examples.

| Metric | Result |
| --- | ---: |
| GPT generation, 300 emails | 89.1 s |
| Local training, tuning, and test evaluation | 3.80 s |
| Teacher agreement, batched test evaluation | 75.0% (45/60) |
| Teacher agreement, single-email SDK calls | 78.3% (47/60) |
| Warm single-email inference, p50 / p95 | 6.80 / 8.33 ms |
| Load bundle in a warm process | 60.0 ms |
| Bundle size, excluding runtime dependencies | 23.77 MB |
| Recommended threshold | None — insufficient calibration data |

Inference timings cover 60 sequential calls after 10 warmups, including JSON preprocessing, tokenization, encoding, and the classification head. Inputs contain 52–96 wordpieces. The [raw results](../benchmarks/email-300.json) include per-class metrics, split hashes, usage, and timings. A second training run reused all 240 training/development responses **without an API key or any API requests** and produced identical head weights and encoder configuration.

Two limitations matter for this dataset:

- **Teacher labels are imbalanced.** Although generation aimed for 50 emails per category, Jev assigned 79 primary, 54 promotion, 41 update, 8 social, 55 forum, and 63 purchase. The fixed test set has no Jev-labeled social examples, so social performance is unmeasured. Generator intentions matched Jev on 224/300 emails; this is a dataset diagnostic, not a correctness score. More teacher-confirmed social examples are needed.
- **Execution mode affects this q8 model.** Five of 60 predicted labels changed between single-input and batched SDK calls; the largest probability difference was 0.278. Reloaded batch predictions exactly reproduce the training report. Single-input results are reported separately. These are material differences, so a deployment should evaluate and calibrate its intended execution mode; this experiment does not change the existing encoder architecture.

Only 10 calibration examples are available, so probability calibration remains unfitted and the threshold recommendation is `null`. The model returns its best category and probabilities without an acceptance decision. This is a working pipeline experiment, not evidence of reliable six-category automatic email routing.

Labeling was limited by HTTP 429 responses, then resumed at 20 requests/minute. The final training-label run reused 35 cached responses and generated the remaining 205 in **10 min 40 s**, including eight timeout retries. That time excludes earlier attempts and the 60 test labels, which were already cached. The API returned the model alias `typesafe-ai/jev`, not an immutable version identifier.

GPT used 6,539 input and 16,138 output tokens: approximately **$0.0068** at the [GPT-5 nano rates](https://vercel.com/ai-gateway/models/gpt-5-nano) of $0.05/M input and $0.40/M output tokens. The 300 saved Jev responses report **$0.00839 market cost** and **$0 charged cost** in Gateway metadata. These are response metadata and a token-price estimate, not an account billing audit; unrecorded timed-out requests are excluded.

## Reproduce

```sh
npm run build
node dist/cli.js prepare-encoder --out .cache/minilm

# 10 batches, 30 fictional emails each. Completed batches are reused on restart.
node scripts/generate-email-dataset.mjs

# Label with Jev, train via the CLI, and measure the reloaded local SDK.
node scripts/test-email-teacher.mjs --encoder .cache/minilm

# Re-measure an existing model using saved labels, with no API calls:
node scripts/measure-email-model.mjs
```

Skip `prepare-encoder` if you already have its files, and pass that directory to `--encoder`. The experiment refuses an existing model output; use `--out models/email-another-run/minilm` for another training run. Existing teacher responses in the dataset cache are reused without API calls. The generator supports `--model` and `--out`; the experiment supports `--dataset`, `--out`, `--encoder`, `--teacher`, `--teacher-rpm`, and `--report`. This script defaults to 20 teacher requests/minute because the live test encountered rate limiting; labeling all 300 fresh inputs therefore takes at least about 15 minutes. Adjust it to your account's capacity. The CLI itself has no default rate cap.

The generator aims for 50 emails per category and keeps its intended categories in a separate metadata file. Those intentions are **not training labels**. Jev sees only the sender, subject, body, and task definition, and supplies the complete probability distributions used for training.

Before calling Jev, the generator selects 60 test inputs (10 per intended category), leaving 240 for training and development. The local trainer then makes its ordinary grouped development split, tunes regularization, and attempts calibration and acceptance selection. Test labels are consulted only for final evaluation. Emails are short English text; the experiment checks all 300 against MiniLM's 256-wordpiece limit before labeling.

| `datasets/email-300/jev.teacher/` | Resumable teacher cache |
| `datasets/email-300/generation/` | Cached GPT generation batches and usage |
| `datasets/email-300/generation-targets.jsonl` | Intended categories, excluded from model inputs |
| `models/email-300/minilm/` | Portable model bundle and training report |
| `benchmarks/email-300.json` | Recorded timing, cost metadata, splits, and evaluation |

To classify a new email locally:

```sh
node dist/cli.js predict --model models/email-300/minilm \
  --state '{"from":"shop@example.com","subject":"Your order shipped","body":"Your parcel is on its way and should arrive tomorrow."}'
```

Use the same `{from,subject,body}` state in the Node SDK. The model returns its best category and probabilities; any routing cutoff belongs to the caller.

For a browser comparison with live Jev, set `AI_GATEWAY_API_KEY`, run `npm run demo:email`, and open **http://127.0.0.1:4320**. See the [email playground](../examples/email-browser/README.md) for setup and controls.
